# 海洛易股票交易模拟器 v3.1 改进摘要

本次升级共完成4项核心改进，旨在提升市场仿真度、封堵套利漏洞、增强AI对抗性。

---

## 一、股价与市场状态持久化

### 【问题背景】
原程序每次刷新页面都会重新随机生成K线历史和股价，玩家的市场操作全部归零，仿真体验严重中断。

### 【解决方案】
1. 修改`core.save()`函数，将整个市场快照存入localStorage，包括：
   - 每只股票的当前价格(prev/cur)、今开、最高、最低
   - 分时K线(minK)、日K、周K、月K完整历史
   - 累计成交量、成交额
   - AI交易压力累计值

2. 修改`core.load()`函数，启动时优先恢复上次保存的市场状态
3. 每30秒自动保存一次市场状态，防止意外刷新丢失

### 【效果】
- ✅ 刷新页面后股价从上次收盘点位继续运行，不再随机重置
- ✅ 玩家对市场造成的价格冲击会被永久记录
- ✅ 仿真过程连续可回溯

### 【涉及代码位置】
- `core.save()` - 保存逻辑扩展
- `core.load()` - 恢复逻辑扩展
- `core.initMarketData()` - 支持从快照初始化
- `core.updateMarket()` - 每30秒自动保存

## 二、30秒交易锁定期机制

### 【问题背景】
玩家可以在1秒内完成"买入→卖出"操作，利用自身买单造成的瞬间价格拉升套利，严重破坏市场平衡。

### 【解决方案】
1. 新增`CONFIG.TRADE_LOCK_SECONDS = 30`配置项
2. 每次买入时在`holdings.buyTimes`中记录买入数量和时间戳
3. 卖出前调用`getSellableQty()`检查，只允许卖出锁定期已满的股票
4. 持仓表格显示锁定数量和剩余解锁时间
5. **FIFO先进先出规则**：先买的先解锁
6. 融资买入、融券卖出同样适用锁定期规则

### 【UI显示】
- 卖出时提示：`"股票在锁定期内（买入后30秒才能卖出）"`
- 持仓栏黄色标注：`"XXX股锁定(XXs)"`

### 【效果】
- ✅ 彻底封堵了瞬时买卖套利漏洞
- ✅ 强制玩家进行至少30秒的持仓决策
- ✅ 市场价格变化更具真实参考意义

### 【涉及代码位置】
- `trade.execute()` - 买卖都加了锁定期检查
- `trade.getSellableQty()` / `trade.getLockedQty()` - 可卖数量计算
- `trade.renderHoldings()` - 持仓显示锁定期
- `marginTrade.executeMarginBuy()` / `executeShortSell()` / `buyBackShort()` - 两融也加锁

## 三、订单簿轻量化改进

### 【问题背景】
原订单簿虽有撮合逻辑，但：
1. 最大可买/可卖数量未考虑盘口实际深度
2. 玩家交易造成的价格冲击衰减太慢，容易长期偏离合理价位

### 【解决方案】
1. **最大可买数量** = `MIN(资金限制, 卖1-卖20总挂单量)`
2. **最大可卖数量** = `MIN(持仓限制, 买1-买20总挂单量)`
3. 新增`CONFIG.PRICE_IMPACT_DECAY = 0.88`，价格冲击每秒衰减12%
4. 玩家冲击与AI冲击分开存储，互不干扰
5. 优化了大单成交后的滑点计算

### 【效果】
- ✅ 玩家无法一次性买入超过盘口深度的数量
- ✅ 价格冲击3秒后仅剩余约68%，5秒后约53%，回归合理速度大幅提升
- ✅ 市场定价更均衡，不会因为一次大单长期失真

### 【涉及代码位置】
- `trade.getMaxBuyQty()` - 加入卖盘深度限制
- `trade.getSellableQty()` - 加入买盘深度限制
- `core.updateMarket()` - 玩家价格冲击衰减逻辑
- `aiEngine.onPlayerTrade()` - 冲击量单独存储

## 四、AI对抗增强升级（双重增强）

### 【问题背景】
原AI交易量偏小、决策频率低、对玩家操作缺乏针对性对抗，玩家可以轻易操纵价格。

### 【解决方案A：整体活跃度提升】
| 参数 | 原值 | 新值 | 说明 |
|------|------|------|------|
| AI价格冲击系数 | 0.5 | 1.2 | ×2.4倍影响力 |
| AI单周期涨跌限制 | ±0.5% | ±1.5% | 波动更剧烈 |
| 散户交易触发概率 | 30% | 50% | 散户更活跃 |
| 散户单次交易量级 | ×1 | ×3 | 成交量大幅提升 |
| AI压力衰减系数 | 0.6 | 0.8 | 影响力更持久 |

### 【解决方案B：针对性反收割逻辑】
1. 玩家每次大额交易都会设置`_playerBigTradeFlag`标记
2. **AI决策周期开始时，庄家(maker)检测此标记**：
   - 如果玩家大买：庄家1.5倍量反向砸盘
   - 如果玩家大卖：庄家1.5倍量扫货吸筹
3. 此检测在玩家交易后3秒内有效
4. **增强版System Prompt**：
   - 明确告知AI市场上有人类玩家可能操纵价格
   - 指导AI观察异常量价波动
   - 要求至少输出3个以上账户的决策
   - 鼓励激进交易和对抗性操作

### 【庄家反收割示例】
```
玩家买入10000股 
  → 价格瞬间拉升 
  → 庄家立刻检测到大单标记
  → 庄家卖出15000股砸盘
  → 价格回落甚至跌破玩家成本线
  → 玩家被套
```

### 【效果】
- ✅ AI交易量大幅提升，市场活跃度明显增强
- ✅ 价格波动更剧烈，更具挑战性
- ✅ 玩家试图大单操纵时会遭遇庄家针对性反制
- ✅ 真正形成"AI vs 玩家"的博弈格局

### 【涉及代码位置】
- `aiEngine.executeCycle()` - 加入庄家反收割逻辑
- `aiEngine.noiseTrade()` - 散户交易量提升3倍
- `aiEngine.buildSystemPrompt()` - 增强版提示词
- `aiEngine._applyPricePressure()` - 冲击系数提升

## 五、离线时间精确记录与推演修复

### 【问题背景】
原有离线推演逻辑虽然设计了 `saveTime` 记录和 `simulateOfflineTime()` 函数，但存在严重缺陷：
1. **页面关闭/刷新时没有事件监听**（无 `beforeunload`），`saveTime` 仅是每30秒常规保存的时间点，不是真正的退出时刻
2. **切换标签/手机锁屏时也不记录**，用户可能离开数小时回来，程序以为只过了几秒
3. 离线推演用 `setTimeout(500ms)` 包裹，不可靠且可能被渲染顺序影响
4. 推演后分时K线未重置，图表显示旧数据

结果：每次进入只是固定化的一小段推演，实际离线时长没有被正确读取和利用。

### 【解决方案】

| 改动 | 位置 | 说明 |
|------|------|------|
| 退出时间独立存储 | `core.load()` | 新增 `helios_exit_time` 独立 key，与 `saveTime` 分离 |
| 双时间源取最新 | `core.load()` | 同时读 `saveTime` 和 `exitTimestamp`，取**较新的**作为参考时间 |
| 系统时钟回拨保护 | `core.load()` | `Math.max(0, offlineSeconds)` 防止负值 |
| 无存档兜底 | `core.load()` | 无存档但有退出时间戳时直接计算 |
| 移除 setTimeout | `core.initMarketData()` | 离线推演改为同步执行，不再延迟 |
| 重置分时K线 | `simulateOfflineTime()` 末尾 | 推演后清空旧分时数据，从当前价格重建 |
| 加载完成即保存 | `window.onload` | 建立本会话的 `saveTime` 基准 |
| `beforeunload` 事件 | `window.onload` | 页面关闭/刷新时精确记录退出时间 + 完整盘面 |
| `visibilitychange` 事件 | `window.onload` | 切后台记录退出时间，回前台刷新保存 |

### 【完整工作流程】
```
退出页面 ──→ beforeunload 触发
              ├─ 写入 helios_exit_time = Date.now()  (精确退出时刻)
              └─ core.save()  (完整盘面 + saveTime)

再次进入 ──→ core.load()
              ├─ 读取 helios_exit_time
              ├─ 取 max(saveTime, exitTimestamp) 作为参考时间
              ├─ 计算 offlineSeconds = (现在 − 参考时间) / 1000
              └─ 若 >5秒 → simulateOfflineTime(实际离线时长)
```

### 【效果】
- ✅ 页面关闭后**任意时长**回来，都能准确推演离线期间的市场变化
- ✅ 切换标签、锁屏、休眠等场景全覆盖
- ✅ 分时图不再显示过时数据，推演后从新价格重新绘制
- ✅ 系统时间调整不会导致负数秒异常

### 【涉及代码位置】
- `core.load()` — 双时间源计算逻辑
- `core.initMarketData()` — 移除 setTimeout，同步推演
- `core.simulateOfflineTime()` — 末尾添加分时K线重置
- `core.save()` — 保存逻辑不变（已有 saveTime）
- `window.onload` — 加载完成立即保存 + 注册 beforeunload / visibilitychange 事件
